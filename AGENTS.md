# Project context

Compari is a procurement-agent app built on Convex + TanStack Start. An
anonymous visitor describes what they need; the backend interprets the
request, researches providers, contacts vendors, collects responses, and
presents an evidence-backed comparison for selection.

## Stack and structure

- React 19 with TanStack Start, TanStack Router, TanStack React Query, Vite,
  and Tailwind CSS.
- Convex provides the backend and database. `src/router.tsx` connects the
  `ConvexQueryClient` and wraps the app with `ConvexAuthProvider` using
  `VITE_CONVEX_URL`.
- Auth uses `@convex-dev/auth` with an anonymous provider (`convex/auth.ts`,
  `convex/auth.config.ts`); per-user data is fenced via `convex/lib/auth.ts`
  (`requireCurrentUser`, `requireOwnedRequest`).
- Static hosting is served through `@convex-dev/static-hosting`
  (`convex/convex.config.ts`, `convex/http.ts`).
- Routes: `src/routes/index.tsx` (landing / onboarding / workspace),
  `src/routes/requests.new.tsx` (new request), `src/routes/__root.tsx`.
- Frontend features: `src/features/workspace/` (onboarding, request intake),
  `src/features/request/` (request detail, outreach status, evidence),
  `src/features/decision/` (comparison views, selection).
- Shared UI: `src/components/ui/` (shadcn-style primitives),
  `src/components/common/` (brand, loaders, dialogs).
- `src/lib/storage.ts` holds the SSR-safe `sessionStorage` helpers; always
  use them instead of touching `window.sessionStorage` directly.
- `convex/schema.ts` defines the domain tables (`procurementRequests`,
  `requirements`, `requestCandidates`, `facts`, `questions`,
  `outreachAttempts`, `conversations`, `proposals`, `evaluations`,
  `sideEffectJobs`, `activityEvents`, `webhookEvents`, ...).
- `convex/requests.ts`, `convex/requirements.ts`, `convex/questions.ts`,
  `convex/conversations.ts`, `convex/outreach.ts`, `convex/users.ts`
  expose the public queries/mutations; `convex/requestDetails.ts`,
  `convex/evaluations.ts`, `convex/diagnostics.ts` serve read models.
- Long-running work runs through internal actions
  (`convex/workflows.ts`, `convex/outreachWorkflow.ts`,
  `convex/reasoningWorkflow.ts`, `convex/rankingWorkflow.ts`,
  `convex/evaluationsWorkflow.ts`, `convex/agentMail.ts`) coordinated by
  `sideEffectJobs` with claim tokens, idempotency keys, and input versions.
- Pure business rules live in `convex/domain/` with `node --test` unit tests
  (`*.test.mjs`); ports are in `convex/ports/`, external integrations in
  `convex/adapters/` (OpenAI reasoning, Firecrawl web research, AgentMail).
- Inbound vendor mail arrives via the Svix-verified webhook in
  `convex/http.ts` (`/webhooks/agentmail`).
- `convex/_generated/` is generated by Convex and should not be edited by
  hand.

Local env vars live in `.env.local` (gitignored, never committed). Treat
deployment URLs, credentials, and environment variable values as private;
do not add them to source or documentation. Required deployment secrets
(`OPENAI_API_KEY`, `AGENTMAIL_API_KEY`, `FIRECRAWL_API_KEY`,
`AGENTMAIL_WEBHOOK_SECRET`) must be set via `npx convex env`.

## Local development

Run these commands from the project root:

- `npm run dev` starts Convex development and Vite together.
- `npm run typecheck` runs TypeScript without emitting files.
- `npm run lint` runs typechecking and ESLint.
- `npm run build` typechecks and builds the Vite app.
- `npm run format` formats the project with Prettier.

When changing files under `convex/`, read
`convex/_generated/ai/guidelines.md` before making changes and follow its
validator, function-registration, and schema rules.

## Commit often

Commit frequently whenever a small, coherent unit of work is complete. Keep
commits focused and use Conventional Commits syntax:

```text
<type>(<optional-scope>): <concise imperative description>
```

Common types are `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`,
`ci`, `perf`, and `style`. Examples:

```text
feat(requests): add persisted comparison results
fix(convex): validate empty input
docs: document local development
```

Before committing, review the diff and run the most relevant checks, usually
`npm run typecheck` and `npm run lint`. Do not combine unrelated changes in a
single commit.
